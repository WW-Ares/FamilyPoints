# 家庭积分

自建的 Docker 家庭积分系统。孩子每天七个维度各 1 分，攒周能量换宝箱，攒星尘换券和零花钱。规则的真值是上层目录的《项目当前开发文档.md》（v1.11，库结构对到 schema 40），这一版是它的技术实现。往前的每一版规则留在 `旧版历史备份/` 里备查。所有能改的数字都在数据库里，设置页里就能改，不需要重新部署。

## 跑起来

### Docker

```bash
cd app
docker compose up -d --build
```

打开 `http://<NAS 的地址>:3637`。

数据存在 `app/data/`，整个目录拷走就是完整备份。

端口在 `docker-compose.yml` 和 `Dockerfile` 里各写了一次（宿主映射 3637 对容器 3637，容器里监听的也是 3637），改的时候两处要一起改。

**搬到 NAS 上跑**看 [部署到NAS.md](部署到NAS.md)：打包、传文件、首次设置、备份、排错都在里面。动身之前先跑这两条：

```bash
python tools/check_docker_copy.py   # Dockerfile 该 COPY 的是不是都 COPY 了
python tools/pack_release.py        # 打一个能直接丢到 NAS 上的包
```

### 不用 Docker

```bash
cd app
python server.py
```

需要 Python 3.11 以上。没有别的依赖，不用 pip install。改端口用 `FAMILY_PORT=9000 python server.py`。

## 从纸质账搬过来

以前用纸笔记，孩子手上已经有星尘和券了，这些要有个正经入口落进库里。走 `tools/carryover_in.py`：

```bash
python tools/carryover_in.py --template          # 生成一份空白清单
python tools/carryover_in.py --items             # 列出能结转的券和卡
python tools/carryover_in.py --show              # 看各孩子现在有多少
python tools/carryover_in.py --file 结转.json    # 预演，库里什么都不动
python tools/carryover_in.py --file 结转.json --apply   # 真写
```

清单是这样，`stardust` 填星尘数，`items` 填券和卡的张数：

```json
{
  "by": "爸爸",
  "note": "纸质账结转",
  "children": {
    "女儿": {"stardust": 46, "items": {"ticket_fun": 3, "ticket_company": 1}},
    "儿子": {"stardust": 12, "items": {"ticket_fun": 1}}
  }
}
```

**结转的星尘不进「累计获得」，等级从零开始。** 手里有多少就能花多少，买券、换零花钱都不受影响；但等级和升级奖励要看他在这个系统里自己挣了多少。纸质时代攒的算进去，孩子一登录就跳好几级，还会连带补出一批券和卡。

券没有保质期，转进来永久有效。卡有（普通和稀有 90 天、传说 120 天），从**结转当天**重新起算，不是纸上那张的时间。超过持有上限的按系统规则拆成碎片，预演时会把超出的数量标出来。

填错了不要删流水。先 `--show` 看现在是多少，再用 `--again` 补一条正的差额（星尘只增不减，补负数会被挡下来）。

在 NAS 上跑（容器已经起来的话）：

```bash
docker cp tools/carryover_in.py family-points:/srv/
docker cp 结转.json family-points:/srv/
docker exec -it family-points python /srv/carryover_in.py --show
docker exec -it family-points python /srv/carryover_in.py --file /srv/结转.json --apply
```

只在搬家时走一次，不是日常工具。

每一版改了什么，写在 GitHub 的 Releases 里，规则的真值与实现状态写在《项目当前开发文档.md》。这一份只讲怎么用和怎么验。

## 第一次用

1. 打开会停在「第一次用，先给管理员定一个账号」。只在「库里一个设过密码的账号都没有」的时候出现。填个账号名和密码，进去。
2. 到「设置 → 家人账号」里，把妈妈、女儿、儿子的账号和密码逐个开通。账号名默认用名字，密码要你自己定一个告诉他们，系统不生成默认密码。开通完他们就能各自登录。这一步只有管理员能做，也就是排序最靠前的家长。**孩子的密码必须正好 4 位数字** —— 他不用账号登录，而是在登录页点自己的头像、按四位数字，底下是九宫格键盘。
3. 顺便把四个人的名字改掉。头像不是拿名字前两个字凑出来的，是另有一套：在自己那张卡上点「换头像」，40 张里挑一张，分爸爸 / 妈妈 / 男孩 / 女孩四组。登录页上摆的也是这一张。
4. 设置 → 假期日历里把今年寒假和暑假的起止填上。填完当天生效，撞上假期的卡片会自动顺延。
5. 设一个许愿池目标，全家一起攒。
6. 想收手机推送的话，各家手机装一个 Bark，把 App 给的 device key 交给你，在「通知与推送」里逐个加上（每加一个都会先真发一条过去，通了才存）。加完把总开关打开。

初始 4 个人：爸爸、妈妈（家长），女儿、儿子（孩子）。管理员默认是排序最靠前的家长。

登录页默认那一屏是一面头像墙：点自己那张头像，再按 4 位数字就进去了。爸爸妈妈不在这面墙上，走右下角那行「家长登录」，还是账号 + 密码。

密码忘了怎么办：孩子找家长或管理员重置，家长找管理员重置；自己的密码自己改（要输旧密码）。管理员的密码万一也忘了，只有两条路，写在《项目当前开发文档.md》的权限那一节。

「设置 → 家人账号」里还能改账号名、把管理员位交给另一位家长、停用某个成员。停用不删记录，历史都留着。

## 每天怎么用

**家长侧**

- 打分：默认七项全满，点掉他没做到的那几项，提交。日期条在上面，先挑哪天再挑哪几项。忘打了第二天中午前还能补，默认补分窗口 2 天。页面最下面是这个月的日历，点某一天能看当天七项和备注，也能直接翻到那天改。
- 审核：待确认的任务、券核销、零花钱兑换、加时申请、求助、**孩子许的愿**、心愿单、校准记录都在这一页。券核销那条会标出「现在批了就能用」还是「已经过不了闸门了」，拖到过点才点同意的话系统会自动改成拒绝。零花钱兑换点同意就等于当场发放（扣星尘、记流水、记下给了多少钱），不同意要写一句为什么。心愿达成不设否决权，一旦点「达成」就不能撤回。
- 任务：分三组排。等你确认的可以确认或退回；进行中的只显示谁在做，撤不掉，按钮写着「撤不掉」并说明得让孩子自己点「我不做了」；等人领的可以直接撤销。上面两个按钮，一个直接派给某个孩子，一个挂到大厅。
- 总览：每个孩子一张速览卡，今日得分、周能量、星尘欠款、券卡碎片、在做几件事都列着。点卡进详细，详细页底部进打分记录。谁还没打分也在这页，点「去打分」直接跳过去。快捷入口里的「心愿与许愿池」分三块：孩子许下来、等你定条件的（给它定条件或者驳回），定好条件正在算的（带进度条，可以撤掉），以及你直接定一个给他的。也能设全家一起攒的许愿池目标。
- 星星时刻：看到他做了件具体的好事，随手发一次。必须写一句具体的话，模板式的「真棒」发不出去。
- 通知与推送：配谁收什么。每个人的 device key 单独存，页面上只显示后四位。带时限的两类（券核销、加时申请）不吃免打扰，其余的在 22:00 到 07:00 之间压着，早上一起发。哪些事会推、推给谁，见下面那张表。
- 规则说明：「我的 → 家里的事」里那三页口径全书（目录 / 打分·周期·结算 / 券·卡·有效期），讲的是这套规矩为什么这么定、边界在哪。孩子那端「怎么玩」是同一套规矩的儿童版。两边的数字全部从当前设置现取，你改过价、改过门槛，它自己跟着变，不会挂着一份三年前的旧数字。

**孩子侧**

- 这周：顶上一行是他自己（头像、名字、等级、今天得了几分、这一周第几天、星尘余额）。下面一张七分表，七个维度各占一行、这一周七天各占一列，拿到分的那格填这个维度的颜色，今天那格套一圈橙框，右边写这一周拿到了几天；表底两句是这一周现算出来的结论，点「看成长报告」进记录页。再往下是正在玩（带倒计时）、要做的事、心愿、最近发生。
- 任务：整页的任务大厅。你在做的在最上面，「做完了」和「我不做了」就在这里；下面是等着人接的，点「我要做」领走；再下面是已经被人接的和已经结束的，谁领了什么、做到哪一步都看得见。
- 宝箱：顶上一行状态（已锁定 / 可以开啦 / 本周已领），后面跟着「还差 6 分到金箱」这类；有箱待开时最上面多一颗橙边胶囊，点它就是开箱（箱子里有什么，点开那一刻才抽）。中间是手上这只箱子的图形，扁平木箱按档位换色，四角点着四颗淡淡的小星；下面一行写这只箱子的保底（「银箱保底 · 6 张娱乐券 + 1 张卡」），再下面一条分段进度线把七档门槛串起来，走到第几档一眼看得见。七档并排各占一列，列里只有箱图、档名、门槛分 —— 每一档到底给什么、随机件多大机会、池子里有哪几样，都在右上那条「查看宝箱详情」进的二级页里摊成一张表。再往下是「星尘直接买」，金 / 钻石 / 王者三档可以花星尘买，每周期最多一次，**买来的箱子不含随机件**。
- 商店：六种券都能买，即买即用。**卡一张不卖**，只能从宝箱里开出来。金、钻石、王者三档箱可以直购，买永远比打出来贵，**而且买来的箱子不含随机件**（随机件只出在打出来的箱子里）。零花钱兑换也在这页：「去换」填星尘数，实时显示扣多少星尘、换多少元；提上去等爸爸妈妈点同意，拿到现金点「收到了」才算完，下面能看到每一条走到哪一步了。
- 许愿：可以自己写下想要什么，条件留白先挂起，等爸爸妈妈来定。定好条件的那些能看到走到哪一步（进度条和「还差多少」），星尘自付的那条攒够了要自己点「付掉」，进度满了点「我做到了」登记达成。条件可以是机器能算的几种，也可以是爸爸妈妈直接写的一句话（那条没有进度条，做到了当面说一声），还可以一次勾好几条、定「做到其中几条算成」（主条画的是做到几条，每条各列一行）。**多选里如果勾了星尘那条，余额够了只是多一个「付掉」按钮**，走这条路还是把星尘留着靠别的条凑数，自己定；系统不会因为余额够就把它算成做到。下面许愿池是全家一起攒的目标，可以把自己的星尘投进去，投多少当场从余额扣。
- 我的：头上是头像、名字、等级胶囊和升级进度（右上那颗小钮进「头像与皮肤」，在 40 张里挑一张）。中间一格三栏：星尘余额、特权道具（点进券包）、这个月的完美日（点进成长报告）。往下依次是心愿屋、成长报告、家庭、图鉴、怎么玩（把那套规矩讲给他听的四页：目录、每天 7 分、宝箱和星星、券和卡；第一次挂一颗「新」，看过就收），最后是修改密码和退出登录。券那一行直接写着现在能不能用、为什么不能（「到点了，21:30 收工，今天先睡」这种），不是点了才告诉你不行。

**周期结算**

默认周六起算七天。结算那天，本周固定分一次性变成星尘（先扣欠的），然后按周能量发对应的宝箱，最后补发升级奖励。结算可以在家长页手动触发，也会在你下次打开时自动补结（v20 起后台线程到点也会自己走一遍）。

**什么会推到手机上**

| 事件 | 推给谁 | 什么时候 |
|---|---|---|
| 有券要用、有加时申请 | 家长 | 立刻，穿免打扰，穿专注模式 |
| 孩子提交任务 | 家长 | 立刻 |
| 任务被确认、被退回 | 孩子 | 立刻 |
| 券批了 / 拒了（带理由）、加时通过 / 没通过 | 孩子 | 立刻 |
| 孩子许了一个愿 | 家长 | 立刻 |
| 心愿被定下条件 / 被驳回 / 达成 / 兑现 | 孩子 | 立刻 |
| 心愿进度够了 | 孩子 | 打分、交任务、结算之后顺带查一次 |
| 今天还没打分 | 家长 | 每天 20:30 之后一次 |
| 本周结算完成、宝箱开出什么 | 家长和孩子 | 周期结算时 |
| 卡片还有 14 天到期 | 卡片主人 | 进入提醒期那一次 |
| 修复任务过点还没交 | 家长 | 每天一次 |

## 数据

- 数据库是一个 SQLite 文件：`app/data/family.db`。每天自动存一份快照到 `app/data/snapshots/`，保留 30 天。
- 设置 → 备份与导出，可以手动存快照，也可以导出全部数据为 JSON。
- 所有余额都是流水求和算出来的，没有冗余字段。任何一次数值变动都能在 `ledger` 表里追到原因。
- 从 v12 升上来的库里，家长名下会残留周期、流水、宝箱和券卡。启动时 `db._migrate_v13` 按 role 反向删一遍，避免结算和历史里冒出「爸爸那周」这种记录。删的都是系统当年自动发给家长的，不是他自己挣的。
- 升级也会补新增的设置项。`_seed` 按 key 补差集，已存在的 key 一律不碰，家里改过的价格和门槛不会被冲掉。

跑测试：

```bash
cd app
python smoke_test.py
python api_test.py
```

两个脚本都用 `data/test/` 里的独立库，跑之前会把它删掉重建，**不碰 `data/family.db`**。想再确认一次：跑之前往正式库写一条记录，跑完看它还在不在。

券的闸门里有三道看时刻（间隔、晚间、硬停止），周期按天切，加时窗口按小时算。这些测试要是跟着真实时钟跑，同一份代码白天是绿的、晚上八点半之后再跑就红，而那种红指向的是空气。所以 `engine.freeze_clock("2026-09-17 18:00:00")` 是整套代码里唯一一个控制「现在」的地方，测试用它把自己钉在某个时刻。`engine._dtnow()` 是全文件唯一读真实时钟的地方，其余一律走它。生产路径上没有任何地方调用 `freeze_clock`。

前端改完必须过这两道：

```bash
# 1. 语法检查。这一步不能省，JS 有语法错整页会白屏
node --check web/app.js

# 2. 未定义标识符粗筛。node --check 只查语法，
#    查不出 `done is not defined` 这类运行时错误（它会让整块界面空白）
python tools/check_undef.py

# 3. 真机巡检：用本地 Chrome 把家长端和孩子端各走一遍，抓 console 报错
#    需要 playwright-core，装一次：npm i playwright-core
NODE_PATH=<node_modules 路径> node tools/e2e_v13.js
```

`check_undef.py` 是启发式的，只挑「被引用但没声明」的名字，会有少量误报，输出的是候选、要人眼过一遍。它存在的理由：`node --check` 只查语法，改块逻辑时漏改一个引用（比如把 `done` 改名成 `hist` 但有一处没跟着改）语法完全正确，只有真正跑到那一行才炸。

`e2e_v13.js`（名字是历史遗留）对着演示库把家长端和孩子端各走一遍，抓两件事：console 有没有报错，以及每一屏该有的东西在不在 —— 两套导航各归各位、登录三态能不能互相退回、倒计时是不是真的在走、券和心愿这条链上的按钮是不是成对出现。它每屏具体盯哪几处写在脚本自己的注释里，加了新的屏就往那儿补一条。

它不点「同意」也不点「撤销」，因为点了就把演示库那条数据花掉，巡检就跑不了第二遍；建心愿、定条件、投币、改图标这类写操作也不要加进来。截图落在 `app/.tmp/v29/`，退出码非 0 表示抓到报错。

点 tab 一律用 `tabTo(page, '名字')` 按名字找，不要写 `nth(3)`。这一版加了「任务」那一格之后，写死的序号全部错位，报出来一堆「某某页里没有某某」，看着像页面坏了，其实是脚本点在了别的页上。

还有一个 `tools/e2e_empty.js`，走的是同一套逻辑但**只走不点**：把家长端五个 tab、孩子端五个 tab 各翻一遍，再进一次详细页和记录页，只截图、不点任何动作按钮。它是给**空库**用的。一条分数一条任务都没有的时候，聚合函数全是除零与空列表的边界，这一版最容易崩的就是那时候。

巡检不打正式库。正式库要屋主自己设密码，巡检碰它就是替人设密码；何况正式库早就有数据了，也测不出空库边界。所以它是打 `tools/empty_seed.py` 造出来的库，只有账号、业务表一张都没行：

```bash
python tools/empty_seed.py
FAMILY_PORT=8099 FAMILY_DATA_DIR=data/empty python server.py   # 另开一个终端
NODE_PATH=<node_modules 路径> node tools/e2e_empty.js          # 默认打 8099
```

改完开发文档跑一遍结构复查，七项判据（文档在位 / 版本一致 / 状态词干净 / 没有断掉的待办引用 / 待办表完整 / 行号不越界 / 前端「这一版」文案在位）：

```bash
python tools/verify_devdoc.py
```

老的 `tools/verify_doc_v17.py` 到 `verify_doc_v29.py` 查的是《规则全书》HTML，那些文件已经进了 `旧版历史备份/`，脚本跟着归档，不要再跑（路径已经指不到了）。

它按文件里的中文标题和关键字做抽查，不按代码里的 setting key 查（文档写的是「硬停止时间」，代码里是 `ticket.curfew_school`，按 key 查一定 0 命中）。行号判据只能查出「越界」，查不出「指到了别的函数」——改完代码顺手核对受影响的行号，别指望脚本替你看语义。

想看着有数据的界面，先造一份演示库。它写 `data/demo/`，不碰正式库：

```bash
python tools/demo_seed.py
FAMILY_PORT=8090 FAMILY_DATA_DIR=data/demo python server.py
```

演示库写 `data/demo/`：一整周的分数、两个已结算周期、星探时刻、各种状态的待办（任务 / 加时 / 求助 / 心愿 / 许愿池 / 券核销 / 零花钱兑换），两个孩子的等级也拉开了（女儿 LV 4，儿子 LV 2）。两个孩子身上具体是怎么安排的、哪一屏看哪一条，写在 `tools/demo_seed.py` 的注释里。

有一条要留意：那条「正在玩」的券是照着建库那一刻写的，半小时后它就玩完了 —— 这是设计如此（没有「结束」按钮，到点自己退出），要再看这一段就重跑一遍 `demo_seed.py`。

## 规则落在哪几个地方

想改数值，优先看设置页，那里按分组列了全部可调项。下面这几处是例外的位置：

- **券的时间额度**：一轮上限（白天）、晚间一轮上限、晚间起点、休息时长、续费窗口、收工点、申请有效时长，都在「券与道具」分组里（共 11 项）。收工点分上学日和周末/假期两项，改完立刻作用于下一次核销，已发出的申请在家长点同意时会按新值重判。有一处要留意：`item` 表里娱乐券的说明文案不含数字，数字一律由使用时的实时提示给，避免改了设置文案还在骗人。
- **任务大厅的名额**：发布时选「只能一个人接」还是「每个孩子各一份」，选完存在 `task.slots` 里（1 和 0），发布之后不能改，要改只能撤了重发。任务奖励的周上限（`task.stardust_weekly_cap`）在设置页，挂大厅的任务在**领取那一刻**才查这条上限。
- **七档门槛、保底券数、随机件概率、直购价**：在「宝箱」表和设置页都能看，改的时候门槛和保底要一起动，文档第 15 章末尾写了原因。
- **道具图鉴（23 张卡 + 6 种券）**：在 `item` 表。改价格、有效期、持有上限都在这里。
- **星球等级表**：设置页「星球等级」分组里，10 档称号、门槛、升级奖励都是 JSON，可以直接改。改门槛不影响已经发过的奖励，因为发过的等级记在流水里。
- **看数的口径**：打分页底部那张月历、总览里的详细页、还有打分记录页，三处用的是同一个接口 `GET /api/score/history`，所以数字一定一致。达成率的分母只算打过分的那些天，「没记录」不等于「没做到」；日历上也是四种底色分开画的，虚线框是没打分，不是 0 分。口径写在《项目当前开发文档.md》3.19。
- **心愿的进度**：七种条件里，五种是单一条件（固定分达标 / 星尘自付 / 完成任务数 / 连续达标 / 完美日），判定走 `engine._auto_progress`；另外两种是拼的，`custom`（自己写一条，家长判）走 `_custom_progress`，`any`（多选条件，勾 2 到 6 条、家长定做到几条算成）走 `_any_progress`，三个函数由 `wish_progress` 按 `cond_type` 分派。多选里那几条各自按自己的类型算一遍，进度是**做到几条 ÷ 要几条**（`need` 存在 `cond_json` 里）；含 `custom` 的多选 `ready` 恒真，因为里面有一条判定权在人手里。要付星尘的那条走 `engine._selfpay_need()`，单选和多选两条路读的是同一笔钱。一条心愿一个锚点，孩子在许愿屋看到的和家长在心愿弹层里看到的是同一份返回值。要加第八种条件，改这一处就够，界面会跟着走。条件的门槛（含「做到几条」）在定条件（`configure`）那一刻锁住，之后改不了。
- **说明页里的话**：孩子端「怎么玩」四页在 `web/child.js`（`K_GUIDE_STEPS` / `K_GUIDE_LIST` / `K_DIM_GUIDE` / `K_TICKET_SAY` 这几张表），家长端「规则说明」三页在 `web/app.js`（`renderRuleIndex` / `renderRuleScore` / `renderRuleTicket`）。凡是会变的数（券价、时长、每周限购、一轮几张、续费窗口、收工时间、卡的有效期与持有上限）一律从接口或设置现取，写死等于家长一改价这一页就开始骗人；写死的只有「一天 7 分、七个格子」这种格局上的常数。版式是两端共用的那一套 `.kd-*`（`web/style.css` 末尾），改一次两边一起变；染色卡改 `--card` 变量，别写 `background`。
- **四条红线**：写死在设置表里，标了 `locked`，接口层直接拒改。不羞辱人格、不碰安全与健康、不追溯已发的奖励、任何道具都不能让每日固定 7 分失效。
- **图标**：`task.icon` / `box_tier.icon` / `wish.icon` 三列，存的是短字符串（图形 token、emoji 或汉字），不是文件。图形清单在 `web/icons.js` 与 `web/icons/` 里，由 `tools/build_icons.py` 生成；券与卡的默认图在 `seed_data.py` 的 `ITEM_ICONS`、宝箱在 `BOX_ICONS`。渲染只有 `web/app.js` 的 `glyph()` 一个出口，改显示样式改那一处就够。**图标不参与任何数值判定**，引擎里没有函数会读它。
- **头像**：`member.avatar` 一列，存的也是短字符串，值是 `web/avatars/<值>.svg` 的文件名。清单在 `web/avatars.js` 与 `web/avatars/` 里，由 `tools/build_avatars.py` 生成；默认款在 `seed_data.py` 的 `AVATAR_BY_NAME`。渲染出口是 `web/app.js` 的 `avatarHTML()`，值是 `engine.clean_avatar()` 洗过的（字母、数字、下划线，1 到 16 位；`B01` 这种编号自动抬成大写，NAS 上是 Linux、文件名区分大小写），静态目录挡路径穿越。**头像同样不参与任何数值判定**。

## 还没做的

- **图标不能上传。** 只能在给定的 382 个候选里挑（自绘 93 + emoji 252 + 汉字 37）。做上传要处理尺寸、格式、存储和内容审核，为一个装饰功能背这条账不值。
- **头像也不能上传，只有 40 张可挑。** 爸爸 / 妈妈 / 男孩 / 女孩四组各 10 张（`D01`–`D10`、`M01`–`M10`、`B01`–`B10`、`G01`–`G10`），都是自绘的。理由是上一条，再加上一条：头像要是个能随便传的图片位，就成了孩子往页面上放东西的口子。40 张里挑一张，这件事不值得做得更复杂。
- **图标没有「按人各一套」。** 一家人共用一套，孩子的设置页里没有换图入口，他只能看。头像是各人各一张，但只能在给定的 40 张里选。
- **多选条件不能再套一层，也不给「全部达成」单独的类型。** 多选里勾的还是那六种单一条件，不能再嵌一个多选（一层已经够表达「几条路任选」，套下去是给写规则的人出题）；想让每一条都做到，把「做到其中几条算成」填成勾的条数就行，用不着另一种条件类型。另外**多选里那条星尘没有「自动付」的开关**，掏钱那一下正是这条条件存在的理由，加开关等于把这一条作废。
- **登录没有失败次数限制，也没有找回密码的通道。** 密码错了可以一直试；管理员的密码要是也忘了，只能停机改库（做法写在《项目当前开发文档.md》第 9 节）。家用场景下这两条都在可接受范围，但要知道边界在哪。
- **卡片效果不可配置。** 二十二种效果各自挂在打分、核销、结算、开箱的不同位置，做成配置项等于把引擎的执行顺序也交出去配，改错一处就是账对不上。要调效果改 `engine.py` 里对应的钩子，不动设置表。
- **偷玩游戏的降级靠人执行。** 系统记的是「这几天设备放客厅用」和到期时间，不锁屏幕。真做设备级管控要的是另一套东西，也不是积分系统该管的。
- **「讲给我听」走修复任务那条线，不在事件通道里生成。** 它是补课不是惩罚，做完由家长确认，跟别的规定动作混在一个列表里。
- **通知能推手机了，但安卓那台收不到。** 走 Bark，只有 iOS 客户端。安卓的 Web Push 背后是 Google 的 FCM，国内到不了，浏览器厂商也把口子关上了。想覆盖安卓得再上一条通道（ntfy 或企业微信群机器人），发送侧已经是可插拔的，加通道不用动调用方，但那是下一轮的事。
- **Bark 推的是明文。** 标题和正文会经过 `api.day.app` 和苹果 APNs。加密要 AES，标准库没有，得引 `cryptography` 或每次调 openssl，为一条推送通道破掉零依赖不值。介意的话别把敏感内容写进通知正文。
- **推送没有失败告警。** device key 填错了，表现就是「手机一直很安静」，不会有人来告诉你。取消订阅、换手机、App 被卸载同样。唯一能自查的地方是设备卡片上那行「上次没发出去：…」，得自己想起来去看。
- 通知只在「真的发出去过」时才标记完成；某个人的设备全挂了，那条通知会试三次然后停手，不会影响别人收。
- 卡片到期顺延只在添加假期日历时触发一次，没有跑定时任务。家里用的话，打开设置页看一眼就够。
- 随机件里「自选普通卡」目前是随机发一张，家长知道孩子想要哪张的话，在后台手动调整。
- 券的核销申请过期是惰性判定的：打开页面或发起新申请时顺手清理，没有后台定时器。对家用来说没区别，但别指望数据库里的状态实时自更新。
- 大厅任务没有「截止时间到了自动下线」。`deadline` 只是显示给孩子看，过期了不会自己撤，得家长手动撤。要自动化的前提是先想清楚过期时孩子手上那份怎么办。
- 撤销不留恢复入口。撤掉的任务进「已结束」，能看到但点不回来；想重新发只能再发一条。
- 放弃过的记录留着（状态是 `abandoned`），但界面上只在「等人领」那张卡片底下显示一行「有 N 次被放回来」，没做逐条明细。
- 挂起的心愿没有时效，可以一直等着父母处理，系统不催也不自动过期，上限只是数量上的。
- 连续达标只数完整周期：点亮那一刻若落在周期中间，那一段不计入，所以凑满「连续 2 周」实际要跨三个周期。
- 心愿墙上不显示「谈了多久」。从许愿到点亮、从点亮到达成各花了多少天，数据都在（`configured_at`、`achieved_at`），但界面上没算给人看。
- 校准的惩罚机制照旧保留，没动。

## 技术选择说明

选 Python 标准库而不是 Go，是因为这套东西的难点在规则和数值，不在并发。四个人的家用系统不需要框架，`http.server` 加一个路由表足够。代价是没有 ORM 和模板引擎，好处是零依赖：镜像小、构建不需要联网装包、也不会有哪天某个库升级把服务搞崩。
