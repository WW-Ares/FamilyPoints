# 响应式适配方案

> 结论先行：现在全站只有「一层自适应」，就是内容条居中、放不下就往两边留白。尺寸本身全是写死的 px，
> 没有任何宽度断点，也没有任何 JS 参与。手机端两头不讨好（小屏挤、大屏空），电脑端是一个 480px 的窄条立在一大片底色里。

本文只做方案，不含代码改动。批准后按第五节的分批顺序实施。

> 行号如今已经指不到 `max-width: 480px` 那一行。那不是写错了，它是「改造前」那张照片。

改成响应式时，这 14 处必须同源。漏一处的后果是宽屏下底栏、弹层或装饰层与内容条错位（装饰层尤其明显，会飘到留白上去）。

家长端已经抽了 `--w-max` 这个变量，孩子端是硬编码 480，登录页是硬编码 440。第一步就是把它们收口到同一套变量。

### 2. 高度是锁死的

- `web/child.css:16`：`body.kid #app { height: 100dvh }`
- `web/parent.css:22`：`body.grown #app { height: 100dvh }`

手机上这条是对的（内容区自己滚，底栏不跑）。电脑上这条是错的：页面本身不产生滚动条，滚动只发生在中间那条 480px 宽的窄区里。鼠标放在两侧留白上滚动，画面纹丝不动，看起来像页面卡住。

### 3. 窄屏有一个确定性溢出

孩子端底栏 `web/child.css:80`：

```css
body.kid #tabs button { flex: 0 0 auto; width: 62px; }
```

5 格不收缩。总需求 = 5×62 + 药丸内边距 12 + 外层内边距 32 = **354px**。屏宽低于 354px 必然横向溢出，且底栏是 `justify-content: center`，溢出是双向的，最左的「首页」和最右的「我的」各被切掉约 17px。

对照：家长端 `web/parent.css:56` 的 `nav-item` 是 `flex: 1` 且带 `min-width: 0`，同屏宽下不会溢出。所以这个坑只在孩子端。

### 4. 没有任何尺寸跟随

全项目 CSS 里 `font-size` 出现 297 次，**全部是 px**。`rem` / `em` / `clamp()` / `vw` 的用量是 **0**。间距、圆角、触摸目标同理。

### 5. 断点只有一个（而且写错了）

全项目 3 处媒体查询：

- `web/style.css:28`、`web/style.css:348`：`prefers-color-scheme: dark`，深色模式，与响应式无关
- `web/child.css:554`：`@media (max-height: 560px)`，唯一一处真实断点

顺带一个笔误：`child.css` 那条上面两行注释写「宽一点的屏」，条件却是 `max-height`，实际管的是横屏矮屏。
注释和代码不一致（已修，见第十节）。

> 2026-09-21 晚补：现在是 4 条 —— 新增 `parent.css:661` 的横屏断点，
> `child.css:681` / `parent.css:645` 两条 `min-width: 900px` 是 P0-2 修的时候加的。

### 6. JS 不参与布局

`innerWidth` / `matchMedia` / `clientWidth` / `resize` / `orientation` 在 `web/*.js` 里 **零命中**。唯一的宽度相关代码是 `child.js:1787` 的 `ic(t[1], 21)`，图标尺寸按像素传参。

## 二、症状分级

按「真坏 / 明显不协调 / 观感」三档，都按代码推算，待截图复核。

### P0 真坏

> **2026-09-21：两条都已修，实测数据见第八节。** 改动落在三处：`child.css` 底栏、`child.css` 与 `parent.css` 各加一段 `@media (min-width: 900px)`。手机侧一处像素没动。

**P0-1 窄屏底栏溢出（≤354px）**〔已修〕

## 三、策略：分层，不一刀切

四条路可选的只有两条，各自的代价都很大，所以按屏宽分层混用。

**路线 A：整体等比缩放（fluid）**
全部尺寸乘一个随屏宽变化的系数。改动机械、与 390 设计稿严格同构，但电脑上一等比就是巨字巨按钮，且要动 297 处字号，回归面极大。

**路线 B：断点重排（真响应式）**
定义断点、宽屏换版式。电脑上能真正利用空间，但每个页面都要重新设计宽屏版式，孩子端首页和宝箱页是设计稿定死的，重排等于重画。

**采用方案：手机段用 A，电脑段用 B，中间过渡段两样都不用。**

| 屏宽 | 做法 | 理由 |
|---|---|---|
| ≤360 | 间距收紧 + 字号设下限 | 空间不够，优先保可读性 |
| 360–600 | 整体等比缩放，390 处系数正好 1.0 | 覆盖绝大多数手机，与设计稿同构 |
| 600–900 | 外壳上限从 480 放宽到 560~600 | 回收留白，但不改版式，成本最低 |
| ≥900 | 家长端换两栏；孩子端只放宽上限、保持居中 | 电脑上家长端有真实使用场景，孩子端没有 |

**孩子端在电脑上不做多列版式。** 理由是它的设计基准是 390 宽画布（见 `.workbuddy/memory/设计基准.md`），宽屏多列等于把宝箱页、券包页、我的页重画一遍，而这些页面上周刚按设计稿对齐完（v38/v39）。孩子实际用的是手机和平板。放宽上限到 600px 就够了。

**家长端在电脑上值得做。** 家长有审核、打分、看记录这三件事，用电脑做比手机顺手得多。起步不必重画页面，`#view` 换成 `grid-template-columns: repeat(auto-fit, minmax(340px, 1fr))`，卡片自然排成两三列，改动小、可逆。

## 四、关键设计决定

### 1. 缩放因子定义在 390

```css
:root { --u: clamp(0.94, 100vw / 390, 1.12); }
```

390 是设计稿基准，这里系数正好等于 1.0，保证设计稿上的像素在基准设备上逐像素不变。上下限 0.94 / 1.12 分别对应 366 和 437 宽，再往外不再缩放。

用 `100vw / 390` 而不是 `vw` 直接当单位，是为了让所有 `calc(N * var(--u))` 的写法保持「N 就是设计稿上的 px 值」，读代码时不用换算。

### 2. 字号要不要跟着变

**要变，但幅度小。** 建议 0.94 到 1.12 之间，且小字（9.5px 一档）设 10.5px 的绝对下限。理由：完全不变（网页观感）在小屏上不可读，等比全变（原生 App 观感）在电脑上会失控。小幅变是两者的折中。

### 3. 变量放哪

`:root`（`style.css:3`）只放三端共用的 `--u` 和 `--shell-w` 基准。各端自己的（`--pad`、`--gap-card`、`--h-tabbar`）继续留在 `body.kid` / `body.grown` 下。

这条是硬约束：项目是「两套皮一份代码」，`child-tokens.css:15` 和 `parent-tokens.css` 的选择器必须挂在 `body.kid` / `body.grown` 上，不能用 `:root` 覆盖，否则两套皮互相污染。

### 4. 图标尺寸要一起处理

`child.js:1787` 的 `ic(t[1], 21)` 把图标尺寸写死在 JS 里。CSS 缩放改造后，图标不跟着变会出现「字变大了图标没变」。两个选择：图标尺寸改由 CSS 控制（`svg { width: calc(21px * var(--u)) }`），或接受图标固定尺寸。建议前者，但单独作为一个小项排期。

## 十、第 2 批收尾：横屏断点（2026-09-21 晚）

### 一上手就撞到一条被漏掉的坏规则

要补家长端横屏断点时，先把孩子端那条唯一的补救量了一遍，发现它不是「不够」，是**反的**：

```css
@media (max-height: 560px) { body.kid .content { padding-bottom: 10px; } }
```

横屏时内容区底距 10px，可底栏本身 71px（药丸 61 + 离底 10）。底距比底栏还矮的后果是
内容尾巴整段滑到药丸底下：844×390 下最后一块内容被压住 60px，且已经是滚动到底，滚不出来的。
这条规则本来是想「多让出 80px 给内容」，实际换回来的是「最后一屏永远读不完」。

顺带证伪两处旧描述：注释写「宽一点的屏」，条件却是 `max-height`（管矮不管宽）；
注释写「把底栏收窄一点」，代码却只动了内容区。

### 改动

| 文件 | 位置 | 改动 |
|---|---|---|
| `app/web/child.css` | `@media (max-height: 560px)`（约 543 行） | 删掉写死的 `padding-bottom: 10px`；改为 `body.kid { --h-tabbar: 58px }` + 底栏整体收一档（离底 10→6、药丸内边距 6→4、图标 21→18、格内上下各减 2） |
| `app/web/parent.css` | 文件末新增 `@media (max-height: 560px)` | `body.grown { --h-tabbar: 64px }` + 底栏整体收一档（外层上下留白 12→8、药丸 62→48、图标 22→19、格内间距 3→2） |

关键点：**底距不再写死，改为跟着底栏的实高走**。两端的内容区底部空档都来自
`calc(var(--h-tabbar) + 16px)` 一处，所以在横屏段落里只要把 `--h-tabbar` 改对，
空档自动跟着底栏走，不会再出现「改底栏忘了改底距」。

### 本轮顺手揪出来的两处

**① 家长端横屏底栏的选中块看着「溢出」。** 截图里选中那颗是一块推不出圆角的奶油色，上下都戳到药丸外面。
根因是 `style.css` 里 v35 换皮**之前**的老底栏还压着它：

```css
#tabs button { max-width: 118px; min-height: 50px; border-radius: 11px; }
#tabs button.on { color: var(--brand-dark); background: var(--brand-soft); }
```

它是 id 选择器，一票压过「`body.grown` + 一个类」那套（`parent.css` 里当初图省事写成了 `.nav-item`）。
手机竖屏下选中的是 62 高的药丸，多出来的几像素看不出来；横屏把药丸压到 48（内高 38）之后，
钉在 50px 的那块就多出 12px。孩子端写的是 `body.kid #tabs button`，本身带 id，所以一直是对的，
**这个坑只在家长端**。补两条带 id 的特化规则把老皮按回去，同时把选中态的渐变、圆角、投影
与孩子端统一（交付包 `parent/tokens.css` 原来给的是浅一档的 `#FFB066 → #FF8A3D` 加实心投影，
两端同一件事看着不一样）。

**② 320 宽宝箱页横向溢出 39px。** 这处**改动之前就有**，是 v38 / v39 留下的，不是本轮引入的
（`.tmp/shots-before/K-320-3宝箱.png` 里 appbar 的「本周能量 22/49」和第七档「完美箱」已经被切掉）。
`.grid3` 用的是 `repeat(3, 1fr)`，而 `1fr` 的下限是 min-content：三颗直购按钮压不到一块，
「星尘直接买」这张卡的最小宽度顶到 328.6，把 `.content` → `.screen` 一路撑开，整页右移。
同一个道理，`.btcols` 七列里的 `.btcol-n` / `.btcol-d` 带 `white-space: nowrap`，
「钻石箱」正好卡在列宽边缘，也压不下去。
改法：两处轨道换 `minmax(0, 1fr)`，标签去掉 `nowrap` 允许换行，`.card--buy` 与它那行价格补 0 下限。
这三处在 390 上本来就装得下，所以改完 390 逐像素没动。
